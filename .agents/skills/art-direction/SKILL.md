# Art direction through game evidence

Read AGENTS.md, the selected ROADMAP task, docs/STUDIO_WORKFLOW.md and only the
relevant environment-library entry. Use the existing game-tested showcase.

1. Define one visual problem and a normal-play-zoom success criterion. Identify
   the actual baseline artifact/images; mark inaccessible screenshots unavailable.
2. Audit permitted existing assets and arrangements before new art. Prioritize
   Swedish silhouette, openings, faluröd panel/white trim/bargeboards and coherent
   ground/plot transitions, not replacing every texture.
3. Supply a short brief: reuse, proposed change, compatible orientations/space,
   rights, fallback, acceptance comparison and the smallest useful second reuse.
   Plan room needs and shell openings together.
4. Assign implementation through the lead; own only the named files. Do not start
   designers or change the overall style/engine. New concepts remain proposals.
5. Review actual exported game images in matched conditions. Distinguish authored,
   exported, game-tested and creator-accepted. Validate routes, interactions,
   roof/light and reload through the designated operator before promotion.

Return concrete pass/revise findings and evidence, not an abstract art essay.
A concept render is not game evidence; a logical sprite alias is not a tested asset.
Stop widening the library if the gain is invisible or the export/access regresses.
