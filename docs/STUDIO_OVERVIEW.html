A small studio.
A world worth discovering.

The creator sets the direction. A lead coordinates bounded work, reusable recipes and evidence. Not every responsibility needs a separate agent.

Static guide, not a live control panel. No agents, jobs or game processes are started here. ROADMAP is the only task queue. The recorded r5 showcase is the game-tested baseline; r6 still needs fresh export/game checks. Household briefs are an offline design prototype, not generated game interiors.

Responsibilities, not permanent departments

Creator

Atmosphere, significant choices, representative feedback and final acceptance. Later areas can retain their surprises.

Lead / integration

One queue, bounded assignments, sequential integration and one operator for shared editor/game resources.

Art Director

A coherent Swedish visual brief. Reuse first; judge actual normal-zoom game views rather than concept renders.

Interior / environment

Fictional households, usable rooms, set dressing and plots. Reusable relationships between objects, not random clutter.

Technical Artist / world data

Distinct responsibilities: verified asset/placement contracts, or traceable geometry and sources. Never infer inhabitants from an address.

Independent QA

Exact diff and evidence, preserved corrections, access and repeatability. Missing checks remain missing.

Normal team: lead + one worker + one independent reviewer. Project Codex configuration caps spawned threads at two; compatible-client loading still needs checking. No pinned worker model or changed permission mode.

Production loop

  1. Choose a sliceOne outcome, base, owner, files and acceptance criteria.
  2. Set the intentVisual brief and a small fictional household story.
  3. Compose a recipePlan shell, openings, room needs and clearances together.
  4. Validate referencesRights, orientations, complete objects and compatible spaces.
  5. Export officiallyUse the existing PZ authoring and packaging path.
  6. Test in the gameFresh save, access, light/roof and clean reload.
  7. Review independentlyInspect actual changes and before/after evidence.
  8. Promote and reuseVersion the tested recipe, preserve choices, measure the next use.

Small choices, coherent variation

Person

Interests and habits. Twenty fictional seeds; names and pronouns do not control selection.

Household

Shared resources, history and compromise. Each resident retains individual needs.

Place

Rooms, storage, garden and local context. Constraints precede weighted selection.

What the household tool actually does

It validates a synthetic request, selects compatible motifs deterministically and writes a separate frozen design brief. It records reasons, omissions, versions and explicit choices. Habits, resources and life events are designer inputs, not implemented placement effects.

It does not spawn furniture, loot, NPCs or weapons, edit TBX sources, or change the game. Existing different outputs—including human edits—are not overwritten.

How houses become reusable

Asset reference → object group → room recipe → house family → plot kit. First prove one room with three variants and reuse it in a second compatible case. Measure manual fixes and actual visual differences before scaling.

What counts as evidence

A concept is not a game screenshot. A passing Python test is not a playable map. An ignored build-folder path is not a remotely accessible picture. Record artifact identity and versions, and curate a small rights-checked fictional-showcase image set.

How the creator remains a player

Use Getaboda and representative fixtures for open design reviews. Later-area floor plans, loot, seeds and discoveries stay out of routine updates unless requested. Bugs, costs and limits are never hidden.
