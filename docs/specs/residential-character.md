# Residential character before larger cottage variants

## Problem and scope

The creator finds the current candidate visually barn-like. Preserve its working
technical baseline, but prioritise a recognisable Småland-inspired residential
prototype before scaling the same form into more candidates. The creator requests
research into cottages/crofts and related boundaries, shrubs, garages and gardens.
The [dated research](../research/smaland-houses-2026-10-18.md) separates regional
evidence, comparative typology and creator preferences.

## Next bounded delivery

Author one separate fictional 6 by 9 `croft_cottage` revision using the existing
size range and permitted local tiles. Keep the playable entrance, rooms and
ceiling. Add a clear entrance treatment, stronger light trim and residential
window rhythm on the road-facing and side elevations. Audit roof/plinth/porch
assets before choosing them. A chimney is desirable but must not be faked as a
working fireplace or assumed technically supported.

Show a maintained plot with one partial boundary, a clear gate-to-door route,
grouped shrubs and entrance/seating flowerbeds. Prefer a stock stone boundary for
the first test if its appearance and collision suit the purpose. Red fencing with
white tops is a requested subsequent option; new sprite work must be assessed
separately. A shed/garage belongs to later family-specific work and needs usable
access when implemented.

Keep actual Getaboda geometry, unknown appearance and existing choices unchanged.
The visual study is an original schematic, not an exported model, surveyed house
or in-game screenshot. The three proposed families are not approved final designs.

## Acceptance and verification

- A normal-zoom view reads as a dwelling: a legible door and approach, contrasting
  opening trim, windows placed for the rooms and no accidental long blank primary
  elevation. Assess by comparison, not a fabricated numerical beauty score.
- The roof and main body have deliberate proportions. A larger house must not
  silently become the same seven-window cottage stretched again.
- The boundary has an opening aligned to pedestrian access. At least one negative
  test rejects a blocked entry or path when placement logic is changed. Preserve
  reserved neighbours and roads; no decorative obstruction can count as a pass.
- Any new generator behaviour gets a focused public-behaviour test and the full
  automated suite. Simple hand-authored visual adjustments get asset checks.
- Official export must pass the metadata gate. In Build 42 verify doors, windows,
  room identity, light, roof, all new boundary collisions and free passage, then
  restart/reload without QA. Report the exact artifact and failures.
- Show the creator actual game views of front/side and the entrance. Technical
  checks and visual acceptance remain separate; the current prototype's tests
  cannot approve the new shape or settle the creator's feedback.

No raw reference imagery, copied game art, detailed private interiors, automatic
property classification or municipality-wide style assignment is part of this
slice. Original game graphics and any distribution license remain a separate
decision if stock pieces cannot provide the desired result.
