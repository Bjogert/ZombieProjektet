# One provisional Getaboda candidate in the game

Continue useful development while the creator gathers owned exterior photos.
Use one frozen local candidate and the approved 45-degree, 1:1 layout proposal
to connect the sized cottage to the existing village road. This is a reversible
prototype, not confirmation of residential use, likeness or the final V1 subset.

The maintained authoring command reads the local register and layout proposal,
checks their shared source hash and candidate identity, then generates one
unrotated cottage in a single authoring cell. Only supported rectangular sizes
are accepted. The source outline remains unchanged; the rectangle, west entrance,
generic rooms, garden and access path are explicit design assumptions. A separate
choice file keyed by stable building ID controls the optional garden.

Preserve original inputs and choices byte-for-byte. Record their hashes in a
local build receipt. Refuse existing outputs, unsupported rotations, out-of-cell
or overlapping placements, malformed roads and unknown choice keys. Keep all real
geometry and build receipts under ignored local directories; stdout has counts
only. No network access or Google image extraction is part of this command.

Acceptance: a synthetic known layout produces the requested house, unchanged road
surface, a connected clear gravel access path, and an optional deck/flower garden.
Two generations are identical; a garden correction changes only that choice's
output. Invalid input leaves no authoring directory. Actual WorldEd export,
metadata validation, game entrance/collision/daylight/roof checks and save/reload
are separate required evidence before calling this pilot playable.

Only one candidate and rotation zero are supported in this slice. No automatic
building classification, exact real garden, inferred private floor plan, full
village assembly or final building selection is implied.
